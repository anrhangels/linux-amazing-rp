# План следующего этапа

**Пункты ниже — план, а не результаты.** Выполненные опыты перечислены отдельно в отчётах [3–4 ноября](report.md) и [8 ноября](research-2026-11-08.md).

## Приоритеты

| Приоритет | Проверка | Необходимый результат |
| --- | --- | --- |
| 1 | Цепочка до первого MessageBox m | Конкретное ошибочное условие и входные значения |
| 2 | Парные запуски ntdll relay / обычный режим | Повторяемое различие с сохранением остальных условий |
| 3 | Динамический resolver startup-кода | Запрошенные символы, адреса, ошибки и их обработка |
| 4 | Причина FALSE из DllMain | Что именно считает инициализацию неуспешной |
| 5 | История памяти позднего потока | Происхождение указателя и связь с очисткой, если она есть |
| 6 | Контроль того же клиента под Windows | Различия до первой точки расхождения |
| 7 | Минимальный тест выявленного API | Проверяемая причина и возможность исправления Wine |

Полный разбор двух найденных открытых обращений к wine_get_version уже выполнен: они относятся к совместимости Schannel/cpuinfo. Поиск дополнительных скрытых проверок остаётся отдельной задачей, но их наличие не следует из этих двух веток.

GE9 и чистый win32 теперь проверены до запуска клиента. Повторять их как совершенно непроверенные варианты неверно. При новом сравнении надо сначала уравнять состояние native CLR, службы, графики и runtime: один из win32-контролей имел START_PENDING вместо RUNNING.

## Правила сравнения

Одна переменная на опыт. Зафиксировать хеши клиента, runner/runtime и префикс; закрыть его процессы перед копированием. Не переносить builtin DLL/ссылки между Wine9 и Wine11. Не менять одновременно версию клиента, Windows version, .NET и тип графического backend.

Для подозрительного различия предлагаются минимум три одинаковых запуска и повтор исходного контроля. Это требование для будущей проверки повторяемости; оно не означает, что все старые опыты имели такое число повторов.

Не запускать тесты бесконечно после получения одинаковой сигнатуры. Ограничивать журнал по времени/размеру. Результаты под инструментированием хранить отдельно от обычного запуска.

## Классификация

| Метка | Критерий |
| --- | --- |
| Инфраструктура не готова | До игрового процесса не дошло; совместимость игры не оценена |
| Лаунчер работает | GUI и загрузка/проверка клиента подтверждены |
| Частичный прогресс | Предыдущая точка пройдена, игрового входа нет |
| Сбой воспроизведён | Сохранены хеши, условия, текст/код, модуль/RVA |
| Игровой запуск | Вход на сервер и управление персонажем с указанной длительностью |
| Стабильность | Повторные старты и длительная сессия, отдельно проверены функции |

После реального входа проверять локации, интерфейс/кириллицу, звук, ввод, сворачивание и выход. Голос проверять с участием второго человека. Эти критерии по состоянию на 8 ноября не выполнены.

## Откат

До опыта сохранять только необходимые локальные конфигурации/копии, после — восстанавливать временные DLL, Debug registry и AppDefaults. Не включать диагностический E_NOTIMPL-экспорт или реконструированный образ в обычную установку. Фикс, который только скрывает исключение, не засчитывать как работоспособность.
