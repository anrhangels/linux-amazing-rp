# План дальнейших проверок

**Ниже — предлагаемые опыты. Их результаты ещё не получены.** Выполненные проверки перечислены исключительно в [отчёте](report.md).

## Порядок

| Приоритет | Опыт | Что он позволяет выяснить |
| --- | --- | --- |
| 1 | Контрольный запуск неизменённого клиента под Windows | Работает ли этот клиент/аккаунт/сеть вне Wine |
| 2 | Чистый префикс, GE-Proton 11-11, .NET 4.8, новый WoW64 | Повторяется ли историческая сигнатура на доступных сегодня файлах |
| 3 | Тот же клиент, GE-Proton 11-9, отдельный префикс | Зависит ли сбой от проверенного runner'а |
| 4 | Традиционный x86 на сопоставимом runner'е | Где расходятся пути инициализации |
| 5 | Актуальный runner, отдельно от исторической базы | Изменилось ли поведение после обновлений |
| 6 | Зависимости по одной, с исходным контрольным префиксом | Есть ли причинная связь между библиотекой и этапом сбоя |
| 7 | Режимы синхронизации по одному | Меняется ли воспроизводимость, а не только время падения |
| 8 | Узкая трассировка памяти и сравнение с Windows | Откуда появляется неверный диапазон |

GE-Proton 9-27 и традиционный x86 на GE 10-32 в старой работе не были проверены. Их можно включить в новую матрицу, но заранее приписывать им результат нельзя. Прямой запуск клиента также остаётся отдельным непроверенным вариантом: он может зависеть от аргументов, рабочего каталога и данных, которые передаёт лаунчер.

## Правила сравнения

Одна переменная на опыт. Не совмещайте обновление клиента, runner'а, .NET, DXVK и режима синхронизации в одном сравнении. Сохраните закрытый исходный префикс или документируйте подготовку каждого нового. Не копируйте префикс с работающими процессами.

Для подозрительного эффекта сделайте минимум три запуска с одинаковыми условиями, затем повторите контроль. Это рекомендация для будущего тестирования; число повторов исторических опытов не сохранено. Отдельно измеряйте задержку до исключения и долю успешных запусков.

Не считайте отсутствие окна сетевой проблемой без журнала. Не считайте `fixme:` причиной падения без связи с исключением. Для синхронизации подтверждайте фактически выбранный backend по runner log: названия и поддержка переменных различаются между версиями.

## Критерии результата

| Метка | Требование |
| --- | --- |
| Инфраструктура не готова | Runner/UMU/Flatpak не дошёл до запуска клиента; вывод о совместимости не сделан |
| Лаунчер работает | Есть окно и завершённая загрузка клиента; игра ещё не проверена |
| Частичный прогресс | Пройден старый барьер, но следующий этап не достигнут |
| Сбой воспроизведён | Сохранены версия/хеши, исключение, модуль/RVA и условия запуска |
| Игровой запуск подтверждён | Вход на сервер и управление персонажем; указаны длительность и условия |
| Стабильность проверена | Дополнительно повторные старты и длительная сессия; описаны проверенные функции |

Для новой успешной сессии отдельно проверьте смену локаций, интерфейс/кириллицу, звук, ввод, сворачивание и завершение. Голосовой чат проверяется при участии второго человека: наличие кнопки или индикатора не подтверждает передачу голоса. Эти функции **не были подтверждены** в старом Amazing-эксперименте.

## Когда завершать опыт

Заранее определите время наблюдения и предел объёма журналов. Если достигнут устойчивый сбой с одинаковой сигнатурой, дальнейший повтор без изменения гипотезы мало полезен. Сначала сохраните результат, затем выбирайте следующий опыт. Не называйте зависание исправленным только потому, что процесс перестал падать и продолжает висеть.
