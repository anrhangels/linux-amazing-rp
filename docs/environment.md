# Окружение и дистрибутивы

> **Обновление 9 ноября:** подтверждены подключение клиента к серверу и два исправления совместимости. См. [актуальный результат](research-2026-11-09.md) и [исходники скриптов](../tools/compat-20261109/README.md). Материал ниже отражает предшествующий этап.

Проверенное игровое окружение — **Arch Linux, Hyprland/Xwayland, Intel Core i7-13650HX и NVIDIA RTX 4060 Laptop**. Успешного игрового запуска на нём нет. Debian/Ubuntu, Fedora и openSUSE в рамках этих испытаний не проверялись.

## Дополнение испытаний 8 ноября

GE-Proton11-11 запускался через SteamRT4; GE-Proton9-27 — через SteamRT3. Дополнительно создан чистый WINEARCH=win32 с непосредственным вызовом GE9 Wine через compatibility layer UMU. Это отдельная конфигурация, не просто переключатель в обычном 64-битном Proton-префиксе.

Подготовка native .NET/WMF и служба подтверждены не одинаково во всех вариантах: GE11 RUNNING и GE9 win32 START_PENDING должны фиксироваться отдельно. Полная матрица — в [новом отчёте](research-2026-11-08.md).

На тестовом хосте не было системного 32-битного загрузчика, поэтому прямой запуск ELF32 Wine вне runtime не был эквивалентным контролем. Работа внутри SteamRT3 не доказывает готовность хостового multilib.

## Подготовка хоста для нового исследования

| Семейство | Где искать базовые инструменты | Особенности |
| --- | --- | --- |
| Arch Linux | `pacman`: Flatpak, Python, Git, file, binutils, vulkan-tools | При традиционном Wine x86 может потребоваться multilib и соответствующие 32-битные графические библиотеки |
| Debian / Ubuntu | `apt`: Flatpak, Python 3, Git, file, binutils, vulkan-tools | Потребность в i386 и пакетах драйвера зависит от способа установки Wine и runner'а |
| Fedora | `dnf`: Flatpak, Python 3, Git, file, binutils, vulkan-tools | Не смешивать автоматически Flatpak-окружение и системный Wine |
| openSUSE | `zypper`: Flatpak, Python 3, Git, file, binutils, vulkan-tools | Названия пакетов и разделение 32-битных компонентов зависят от выпуска |

Это перечень категорий инструментов, а не проверенная команда установки Amazing. Имена пакетов сверяйте с конкретным выпуском дистрибутива. Переход на новый WoW64 меняет потребности по сравнению с традиционным x86; установка произвольного полного набора `lib32` не является установленным исправлением `aggmain`.

У Flatpak есть собственные runtimes и расширения графического драйвера. Работа `vulkaninfo` на хосте полезна, но не доказывает доступность того же стека внутри sandbox. Записывайте обе стороны, проверяйте доступ к файлам и runner log.

## Минимальная запись хоста

```bash
uname -a
cat /etc/os-release
printf '%s\n' "$XDG_SESSION_TYPE" "$XDG_CURRENT_DESKTOP"
flatpak --version
flatpak list --app --columns=application,version
flatpak list --runtime
```

Если инструменты установлены:

```bash
lspci -nnk
vulkaninfo --summary
nvidia-smi
```

Последняя команда относится только к NVIDIA с подходящим драйвером. Ошибка отсутствующей команды означает отсутствие утилиты, а не доказанный дефект GPU. Версию UMU и runner'а сохраняйте из их реального запуска; системный `wine --version` не описывает Proton, выбранный в Faugus.

## Что ещё важно

Запишите локаль, разрешение и число экранов, используемый GPU на гибридной системе, расположение клиента и файловую систему. Кириллица в пути и локализованная папка загрузок — условия теста, а не автоматически установленная причина сбоя.

Не обновляйте весь набор компонентов в середине серии сравнений. Если обновление необходимо, начните новую серию и сохраните обе конфигурации. Наличие современного драйвера полезно для корректного окружения, но причинная связь драйвера с наблюдавшимся чтением `MEM_FREE` не установлена.
